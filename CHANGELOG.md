# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Legend Echoes** — standout workouts (relative PB, clutch overtake, mythic size, or the first flag of a challenge) are minted as living, claimable trophies in the Echo Chamber: remixed photo (when a Hall of Roasts poster exists), coach-voiced narrative, and a power rating. Undefeated Echoes sit on the challenge page and the coach keeps referencing them. Anyone in the group can declare war (7-day window, one active challenge per Echo); beating the metric claims the Echo, raises the bar to the new feat, grows the lineage, and the originator keeps Legacy status. Three failed claims — or the end of the competition — makes it Immortal and awards the Echo Immortal dog tag (claimants earn Echo Slayer). Season chronicle: Book of Echoes.

### Fixed
- **Login spinner never giving way to the app** — visiting `/login` deleted the access token and waited on a refresh with no timeout, so a slow or hung `/token/refresh/` left people on the loading bar; a 5s `localStorage` wait after password login threw uncaught and froze the spinner for good. The form now keeps a still-valid access token, caps silent refresh at 8s, always clears the loader, and a stale in-flight refresh can no longer wipe the tokens from a login that just finished.
- **Echo claims now move the bar** — a successful claim updates the Echo's metric, power and title to the winner's workout (the next challenger has to beat *that*), and a claiming workout cannot also plant a fresh Echo. Immortal Echoes close any open wars so they cannot be stolen after the season ends.

## [0.39.0] - 2026-08-22

### Added
- **Weekly coach vote in each challenge** — participants pick next week's Drill Instructor from the ballot (built-ins plus roasters created by people in that challenge). Votes tally Monday 07:15; the winner takes the megaphone, a handover line lands in Coach's Corner, and a live countdown shows how long they are on the clock. You can change your vote until the switch.
- **Anyone can create their own roaster** — custom Drill Instructor personas are no longer admin-only. Staff can add, edit and delete every roaster (including built-ins and other people's). Everyone else can only create, edit and delete the ones they made.

### Changed
- **The roaster sits above coach pings** on the Coach page, with a Create yours card and a Manage button for every user.
- **Hall of Roasts lives on the challenge page** — it is per-competition (top remixed photos of that challenge), not a global box on the Coach page.
- **Challenge activity feed shows the latest 5** — older workouts open in a day-grouped history sheet ("N older activities") instead of stretching the box.
- **Hot-or-not: one rating per picture per user** — a second swipe on the same roast is refused (409); already-rated cards drop out of the selection stack (the "judge them all again" replay is gone). Hall of Roasts still shows every card.

### Fixed
- **Health Connect workouts not importing on their own** — several breaks on the same path: the Android SDK only restores background sync after `configure(host)`, which ran solely at link time, so a process kill stopped Health Connect pushing to Open Wearables; launch restore now re-configures and always re-arms WorkManager (a stale `syncActive` flag used to skip the restart). The Celery worker never imported `custom_user.health` (autodiscover only loads `tasks.py`), so the hourly poll was unregistered even when the PeriodicTask row existed; `custom_user/tasks.py` now loads it, and the `health_sync` beat job is re-seeded if it was missing. The mapper also accepts Open Wearables' `start_datetime` / `end_datetime` aliases and follows nested `pagination.next_cursor`.

## [0.38.1] - 2026-08-22

### Fixed
- **Desktop menu bar sat on the centre-left** — `animate-nav-rise` uses `transform`, which overrode `md:-translate-x-1/2`, so the dock's left edge was at 50% of the viewport. The pill is now `md:mx-auto` inside a full-width wrapper.
- **Profile pictures 406'd** — avatar fetches sent `Accept: image/*`, which DRF's JSON renderer does not match, so every `/api/user/<id>/picture/` (and persona/photo-post pictures) returned Not Acceptable. The client no longer sends that Accept, and the picture endpoints accept any `Accept`.

### Fixed
- **Goal-edit rescore no longer flattens every activity to the same points** — changing a target/metric rewrote `points_raw` then left `points_capped` at that uncapped raw (or, after the 30s Celery throttle skipped the recap, applied daily/weekly caps in UTC day buckets and ISO week-without-year). Evening workouts on different local days shared one daily cap, so a whole-challenge recap slammed long activities into the same number. Raw scores are now recomputed per workout, caps are reapplied immediately in the site timezone, and week buckets include the ISO year. Already-flattened challenges: re-save the goal, or `python manage.py rescore_goals` (optionally `--competition ID`). Workouts that actually exceed the daily cap (default Exercise: 60 min) still tie at that cap — that is the cap, not this bug.
- **CrowdSec / fail2ban 401 bursts while using the app** — the access JWT lasted 5 minutes, then every poller *and* every avatar fetch hit `/api/` with a dead token at the same instant (8–20 × 401 in a second, which `http-auth-bf` / `http-generic-bf` treat as credential stuffing). The client now refreshes 60s before expiry (one shared `POST /token/refresh/`), picture fetches wait on that refresh and run at most 4 at a time, the Android OkHttp UA is no longer the default `okhttp/4.x`, the login screen no longer calls `GET /user/me/` unauthenticated, and the access token lifetime is 15 minutes.
- **Photos can only be attached to your own workout** — the camera used to post into the main coach feed or onto any thread. Pictures now always hang under your latest workout comment (the camera is on every thread, including posts that @-mention you); someone else's workout is never the parent.
- **Coach name no longer truncates on mobile**, and the challenge-page reply row (camera + input + send) stays on-screen instead of pushing the send button off the viewport.

### Security
- **APK update link is a hardcoded path on a sanitized http(s) origin** — the native server-address field no longer flows into `href` as raw DOM text (CodeQL `js/xss-through-dom`).
- **User list no longer exposes co-participants' last names** (emails, staff flags, Garmin/Health ids, equalizer factors were already stripped; first name stays for the transfer-ownership picker).
- **Activity goals and teams cannot be re-parented** onto another competition via PATCH.
- **X-Accel-Redirect paths reject `..` / absolute names** so a poisoned ImageField cannot point nginx outside MEDIA_ROOT.
- **Help accordion no longer uses `dangerouslySetInnerHTML`** (static copy is JSX).
- **Team join is on the `join` throttle** (was unthrottled join-code-adjacent).
- **Celery POST is allowlisted** — staff can only enqueue known operational tasks, not an arbitrary registered name.
- **Uploaded images are verified and re-encoded with Pillow** (pixels, not the client Content-Type).
- **Per-resource permission classes** replace duck-typed `IsOwnerOrReadOnly` on workouts, competitions, teams, and goals. Points stay read-only + authenticated.
- **Permissions-Policy allows `camera=(self)`** so photo posts (`<input capture>`) are not blocked.
- **Logout now actually wipes the session on shared devices** — the logout/login/register flows reset only 6 of the 12 RTK Query slices, and the store re-persisted itself into `localStorage.appState` ~2s after `localStorage.clear()`, so admin site settings, team rosters and other cached API data survived "logout" in the browser. All three flows now dispatch the store-wide `RESET_STORE`. Also: `/logout` added to the reauth guard's public paths (the bottom nav's still-subscribed `me` query 401'd mid-logout and redirected to `/login?redirect=/logout` - the next login navigated back to /logout and wiped the just-issued tokens, a login-logout loop); the native app's server address (`wc_server_url`) survives the wipe (its loss stranded the APK's registration and post-logout API calls); per-device user leftovers (`wc_equalizer_inputs`, coach ping baseline) are cleared on login/logout; `health_developer_password` added to both secret scrub lists (was missing from the Redux persistence scrub and the Sentry redaction).
- **Open Wearables developer login no longer internet-exposed** — the new `/health/` route proxies the whole OW API for the phone flow; the developer login endpoint (admin-equivalent for the OW instance) and the API docs/schema are now 404 through it. Phones never need them (tokens come from the single-use code redeem); our backend logs in via the internal URL.

### Fixed
- **Android Java/Kotlin quality** — Capacitor's placeholder tests still lived under `com.getcapacitor.myapp` and asserted `com.getcapacitor.app` (they would fail if CI ran them). Replaced with a real-package context test and host-allowlist unit tests. Also: `allowBackup` off (Health Connect tokens must not hit cloud backup), FileProvider limited to app cache instead of the whole external volume, Health plugin coroutines cancelled on destroy, and SDK errors logged instead of being forwarded into the WebView.
- **CodeQL alerts on the Coach photo preview, APK update link, and equalizer storage** — the preview `<img>` now draws a decoded bitmap (not a raw blob URL of the pick); the in-app update button always links the same-origin `/download/workout-challenge.apk` (the JSON-supplied URL is ignored, and `getServerUrl` was never imported so the href was `undefined/…`); the equalizer no longer writes gender to localStorage (it already lives on the profile).
- **Editing a challenge goal now rescores the whole challenge** — a target/metric change previously only enqueued a cap recalc on the old `points_raw`, so changing 150 min → 300 min left every workout at the old raw score. Raw points are recomputed for every workout in the challenge window, then caps are reapplied from day one.
- **Coach photo posts can come from the gallery, not only the camera** — `capture="user"` on the file input forced the camera on phones and hid the library. The composer now offers Camera and Gallery as separate actions (gallery is a file input with no `capture` attribute).
- **Switching the coach no longer rewrites every old post's picture** — the feed serialized `config.persona` live, so picking a new persona replaced avatars on historical bubbles. Each message now snapshots the persona that was on duty when it was written.
- **Health Connect 5 km runs showing up as ~2.x km** — when Open Wearables omitted `distance_meters` (common on Android), `Workout.save` invented a MET×duration estimate (easy-run MET 7.8 × 20 min ≈ 2.6 km). Imports no longer estimate distance; metres/km/pace are parsed from the OW payload, and a 5.0 that is already kilometres is not divided by 1000 again.
- **Health "Re-Sync" on the Android app now also nudges the phone** — the button only polled the server, so nothing new arrived until Health Connect had already been pushed. Tapping it now kicks native background sync first.
- **Protected pictures refuse indexing and shared-cache storage** — `robots.txt` now disallows `/api/`, `/media/` and `/protected-media/`; picture responses send `Cache-Control: private, no-store`, `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` and `Cross-Origin-Resource-Policy: same-origin`. `/media/` stays 404 and `/protected-media/` stays nginx-`internal`.
- **Password-reset polish: real error messages and a working footer link** — the reset flow (login → "Forgot Password?" → email link → new password) existed end-to-end but had two visible defects: the reset email passed the raw reply-to *list* to the footer template (`mailto:['support@…']` / `mailto:None` - every other email passes a single address), and the frontend only read `parsedError.detail`, so the two most common failures - an invalid/expired reset link and a rejected weak password (both DRF `non_field_errors`) - surfaced as "Bad Request (400) - Unknown error". The email now gets a single reply-to address like its siblings, and both reset API helpers extract the first human-readable message (`detail` / `non_field_errors` / field errors). Nine new tests cover the flow: identical 200s for known/unknown addresses (no user enumeration), case-insensitive email lookup, bad uid/token rejection, weak-password rejection, session blacklist + token one-time use on reset, and the email task's content.
- **Coach-page photos never got the roast remix (and never reached hot-or-not)** — the Coach page's photo button always posts the picture as a reply to the coach's latest message, and the reply pipeline (`post_reply_reaction`) had no roast path at all: it posted the text reaction and ended, so no edited picture was ever generated and the hot-or-not box (which only lists coach reactions carrying an image) stayed empty. Photo replies now earn the same roast remix as thread-root photo posts; the roast hangs under the thread root so it renders in the thread.
- **Stale avatars after re-uploading a profile/persona picture** — the authenticated image loader cached blob URLs by (stable) URL forever, so a re-upload kept showing the old picture until a full reload. Uploads now invalidate the cache entry (and blob URLs are revoked on eviction). Also: a removed picture no longer keeps rendering its stale blob.
- **"What's new" popup never appeared in the Android app** — it fetched a relative `/api/version/`, which resolves to the WebView's own `https://localhost` origin instead of the server.
- **Challenge page error box showed "undefined /"** — the stats-error branch rendered the competition query's error fields.
- **Dashboard crash when a competition's stats query fails** — the row dereferenced `stats.competition` unguarded and the error boundary took down the whole page; it now renders a dash.
- **Team creation failure was silent and threw** — `result.data.id` was used without checking the mutation result.
- **Activity-goal form robustness** — cleared optional min/max fields no longer send `""` (DRF 400); error messages accumulate correctly (functional state updates, only the last one survived before); a retry after a partial save no longer duplicates the goals that were created on the first attempt (the form re-syncs from the server state).
- **Goal boxes and "How Points Work" now show the same numbers** — the info view scales kcal/kJ/km targets and limits by your personal equalizer factors, matching the challenge page (it showed raw values before).

### Performance
- **Capped-points recalculation is batched and race-free** — the recalc task selected every Points row's workout one query at a time (N+1 via the Scorer's per-row dereferences), wrote one full-row UPDATE per row, and deleted RecalcRequests created mid-run unprocessed (stale caps until the next coincidental re-trigger). Now: `select_related`, `bulk_update` (500-row batches), an id snapshot so mid-run requests survive, and one `in_bulk` goal fetch for all groups.
- **Scorer bulk paths batch their writes** — new workout / new goal / competition date changes / user joins / scaling-factor and sport-factor re-scores all wrote per-row INSERTs and re-read the sport factors per row; they now use `bulk_create`/`bulk_update`, hoisted factor maps, and `select_related`/`prefetch_related` (a 500-workout user joining a 3-goal challenge went from ~1500 sequential INSERTs to a handful of round trips). A start_date shortening only enqueues recalcs for (user, goal) pairs that actually lost points (was the full cartesian product).
- **Hourly syncs no longer churn caches for nothing** — re-saving an unchanged activity early-returns before the stats-cache bust + recalc enqueue (previously every known activity, per user, per hour, invalidated every challenge snapshot it touched). Garmin/Health syncs load only the fetched page's ids instead of the whole table's provider rows; Strava's redundant whole-table id set is gone (the per-page map already covers it, including the cross-account takeover guard).
- **Activity feed endpoint is cached per stats generation (30s TTL)** — it rescanned the competition's entire Points table twice per request, uncached, on every 60-90s poll; it now shares the stats generation key (permission check still runs first on every request).
- **Settings resolution cached for 60s** — Strava rate-limit checks, LLM config and OW connector config each hit the SiteSettings row on every call; now cached briefly and invalidated on save, so admin edits still apply without restart.
- **Stats tail: one query less** — owner `select_related` and `len(members)` instead of a second COUNT query.
- **Weekly/leaderboard emails: one task per user** — the scheduler joins produced one row per active competition, so users in N challenges got N duplicate emails; both queries now use `distinct()`.

### Added

- **"How Points Work" info view in every challenge** — a new info button in the challenge header opens the actual scoring math for THAT challenge: each goal with its target/period as a plain formula (`points = minutes ÷ target × 100 × activity factor`), its per-activity/day/week floors and caps, whether daily step totals count, the site-wide activity-type factors, and your personal equalizer factors (effort %/distance %) with a pointer to the goal equalizer.
- **Admins can tune the points calculation per activity type** — Admin Settings → "Points Calculation" opens an editor for site-wide multipliers per sport (e.g. Swim ×1.5, Walk ×0.8; 1.00 = neutral). Stored on the Site Settings row (`points_sport_factors`, new migration `site_settings/0005`), applied by the scorer on every scored workout (60s-cached), and saving re-scores all affected existing points rows + enqueues the cap recalc automatically. Read back for everyone via `GET /api/points-factors/` (powers the info view above).

### Fixed
- **Activity-goal edits now refresh the challenge page right away** — the goal form only invalidated its own cache namespace, but the page reads stats + feed, so edited/deleted/new goals lingered until the 90s poll (and the alert text claimed "up to 10 minutes"). Saving now reuses the workout-edit pattern: stats/feed re-fetch immediately and again at ~15s/35s (bracketing the server's async cap recalc), so the boxes and the "How Points Work" info view reflect the change within a minute. The factors shown in the info view are also refetched on every open (were cached up to 12h after an admin edit).
- **Migration drift in drill_instructor resolved without touching the DB** — `0012` added the one-comment-per-workout unique constraint as a deliberately DB-only guard (its IntegrityError is what suppresses double coach comments under concurrent tasks), but as a plain `AddConstraint` it also entered the migration *state*, so `makemigrations --check` permanently wanted to drop a protection the code relies on. `0013` is a `SeparateDatabaseAndState` state-only removal: the model state is clean again and the database keeps enforcing the guard (verified: sqlmigrate is a no-op).
- **Goal equalizer forgot your inputs on every open** — the modal only ever loaded the profile gender and otherwise fell back to the hardcoded defaults (35y/180cm/75kg), because the raw inputs are intentionally never sent to the server ("stay on your device") - but they were never stored on the device either. They now persist in localStorage (`wc_equalizer_inputs`) and are pre-filled on reopen; still only the two derived percent factors ever leave the device.
- **Garmin: daily step totals were imported as workouts** — some devices/loggers push all-day step summaries into the Garmin activity list; the sync mapped them to a generic "Workout" row. Step-type records (`steps`/`daily_steps`/`all_day_steps`/`step_tracking` typeKeys - exact matches only, so real stair-stepper workouts keep importing) are now skipped, and a row imported by an earlier version is deleted again on the next sync (per-object delete, so points recalc fires). Covered by two new tests (skip + cleanup, stepper still imports).
- **Health Connect "host not found" in the Android app** — the connection code handed phones the LAN/internal Open Wearables address (`HEALTH_PUBLIC_URL`, e.g. `http://<server-ip>:8001`): unreachable on mobile data and mixed-content-blocked under the HTTPS app on Wi-Fi. The container nginx now serves the OW API under the app's own domain at `/health/` (variable `proxy_pass` + docker resolver, so nginx boots fine when the health profile is off; verified end-to-end against a live stack), and `HEALTH_PUBLIC_URL` defaults to `MAIN_HOST/health` instead of the internal hostname - no reverse-proxy rule or LAN exposure needed any more (`OW_BIND` can go back to loopback). The app also names the cause when the health server can't be reached instead of surfacing a raw fetch error.
- **Android app updates rejected ("app not installed"), forcing uninstall + reinstall** — the `apk` CI job had no signing material, so `app/build.gradle` silently fell back to the debug key: every CI runner generated a fresh ephemeral debug keystore and **every release APK carried a different signature**. Android refuses in-place updates across signing identities (and the locally-built APK is release-key-signed, mismatching CI too), so no working update path existed. The CI now signs releases with the real release key when the `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD` secrets are configured (it materializes `~/.gradle/workout-signing.properties`, which `build.gradle` already auto-discovers); forks without the secrets keep the debug fallback. Note for existing installs: an APK signed by a CI debug key must be uninstalled once - afterwards every update installs in place, data kept.
- **App "disconnects" after a while (stale data, missing profile pictures) although the session is valid** — root cause was token-refresh starvation: `POST /api/token/refresh/` shared the brute-force `auth` throttle bucket (`30/hour`, per IP) with password login, while the app legitimately needs one refresh per 5-minute access-token lifetime (~12/hour per foreground device, plus cold-start auto-login) — and mobile users share the per-IP budget via carrier-grade NAT. Once the bucket was empty, refresh answers 429 and the frontend treated *any* refresh failure as "session dead": it hard-redirected to /login and `apiRefreshToken()` even **deleted the still-valid refresh token** on 429 *or a mere network hiccup*, turning a transient throttle into a forced re-login (which then failed too - same bucket). Fix: refresh now has its own `auth_refresh` bucket (`300/hour` - a 256-bit rotating token is not password-guessable), `auth` stays at 30/hour for real credential guessing; the frontend only logs out when the refresh endpoint confirms the token is dead (400/401), and keeps tokens + retries on 429/5xx/network errors. Regression tests cover the scope split, throttling independence and rotation reuse-rejection.
- **Android: "Save & reload" on the server-address field did nothing** — the ServerField `<form>` was nested inside the login `<form>`. Submit events never cross a form boundary while bubbling (the outer form's submission behavior stops propagation), so React's root-delegated `onSubmit` on the inner form never fired: the address was never stored, the page never reloaded, and every login attempt then went to a server that was never set (reproduced in headless Chromium: save handler 0 calls, localStorage empty). Never noticed before because the per-deployment APK (baked `MAIN_HOST`) never requires saving. ServerField now renders as a sibling of the login form - click *and* Enter both save reliably.
- **`apk` CI job: Capacitor CLI requires Node >= 22** — the job pinned Node 20, so `npx cap sync android` died with "The Capacitor CLI requires NodeJS >=22.0.0" after the web build had already succeeded; no release APK has been attached by CI since the Capacitor 8 upgrade. The job now sets up Node 22.
- **Android: profile pictures STILL missing + forced login on every app reopen** — two follow-ups to the avatar/session work: (1) the native avatar loader passed `CapacitorHttp`'s blob response straight to `FileReader.readAsDataURL()`, but the Android bridge returns binary bodies as a **base64 string** (`HttpRequestHandler.readStreamAsBase64`), not a `Blob` - the call threw a TypeError, the catch swallowed it and every avatar silently fell back to the placeholder; the loader now builds the `data:` URL directly from the base64 payload + response Content-Type (whitespace-stripped - Android's `Base64.DEFAULT` wraps lines). (2) `apiRefreshToken()` (the login page's auto-login) stored only the new *access* token and dropped the *rotated refresh token* - with `ROTATE_REFRESH_TOKENS` + `BLACKLIST_AFTER_ROTATION` the just-used refresh token is dead the moment the response arrives, so localStorage kept a blacklisted token and the next refresh (minutes later) failed: every app reopen ended back at the credentials form. The rotated refresh token is now stored, and the Welcome page (the APK's cold-start URL) redirects straight to the dashboard when a refresh token exists - an expired one still bounces to /login via the normal reauth path.
- **In-app update banner never appeared in the Android app** — the check fetches `/download/apk-version.json` from the WebView (origin `https://localhost`), but nginx's `/download/` location sent no `Access-Control-Allow-Origin`, so the WebView hid the response and the check died silently in its catch. The location now answers with `Access-Control-Allow-Origin: *` (public, unauthenticated files).
- **Android: "OWHealth plugin is not implemented" + missing avatars** — the custom OWHealth plugin was registered *after* `super.onCreate()`, but `BridgeActivity.onCreate` builds the Bridge and consumes the plugin list in that call, so the plugin never existed; it is now registered before (Capacitor's documented order). Profile/persona pictures failed silently in the WebView: the authenticated loader now uses `CapacitorHttp` (native OkHttp - no WebView CORS/blob quirks) and renders via `data:` URLs (`safeImageSrc` allows `data:image/`).
- **Health Connect linking in the Android app died with "Failed to fetch"** — the app redeems the invitation code from its Capacitor WebView (origin `https://localhost`), but the bundled Open Wearables defaults `CORS_ORIGINS` to *empty*, so its CORSMiddleware never emitted `Access-Control-Allow-Origin` and the WebView blocked every response (preflight and POST both). The `openwearables` service now sets a default CORS allowance for the app origin (`OW_CORS_ORIGINS` knob) — **as a JSON list** (`["https://localhost"]`), because pydantic-settings JSON-decodes list-typed env vars and a bare string makes OW crash at startup (verified against the pinned image).
- **The `apk` CI job never shipped an APK** — every release so far carries only `docker-compose.yml` + `.env.example`: GitHub Actions sets `CI=true`, which makes the CRA build inside the apk job treat the (tolerated) ESLint warnings as fatal errors, so "Build web bundle" died before Gradle ever ran. The step now builds with `CI=false`, matching local builds - reproduced and verified. The upload step had a second latent bug: `gh release upload file.apk#workout-challenge.apk` sets the asset *label*, not its name, so the release would have shipped `app-release.apk`, which `update_apk_from_release.sh` never finds - the step now renames the file before upload. Release `0.11.0` was back-filled manually (locally built APK, correctly stamped 0.11.0/101).
- **`update_apk_from_release.sh` no longer needs the gh CLI** — it now uses plain curl + python3 (no interactive `gh auth login` on the server, so it is actually cron-friendly on a fresh VPS), auto-detects the GitHub repo from the running image's `org.opencontainers.image.source` label (git remote / `REPO_SLUG` as fallback), works on public repos without any token (`GITHUB_TOKEN` only for private forks), and fails with a clear "release X has no APK attached - did the apk CI job succeed?" message instead of gh's opaque pattern error.

### Security
- **Dependabot alert 110 (`postcss`, CVE-2026-69153) resolved** — the flagged instance is `postcss@7.0.39`, nested under `resolve-url-loader` in the react-scripts 5 build chain; no resolve-url-loader release supports postcss 8, so it is structurally not upgradable (forcing it would break the CSS build). The vulnerable code path - processing attacker-controlled CSS with a malicious `sourceMappingURL` - is never exercised: the loader only rewrites our own checked-in CSS at image build time. The first-party postcss (root devDependency) floor is now pinned at `^8.5.23` (lock already resolved 8.5.25, i.e. patched) so it can never regress into the vulnerable range, and the alert is dismissed on GitHub as tolerable risk with this justification.
- **CodeQL `js/xss-through-dom` on the persona avatar** — the pre-upload preview in the persona editor passes a DOM-derived object URL through the persona payload into `<img src>`. Practically unexploitable (browser-minted `blob:` URLs can't execute script in an image), but the sinks are now whitelist-guarded: only `blob:` and same-origin relative URLs may reach `<img src>` (`safeImageSrc()` in `PersonaAvatar.js`), and - the genuinely valuable part - the JWT-carrying image fetch in `protectedMedia.js` now only requests same-origin relative paths, so a malicious API payload can never point the authenticated fetch at an attacker host to exfiltrate the token.
- **All uploaded pictures are no longer public** — uploaded images (Drill Instructor persona pictures *and* user profile pictures) must never be reachable without a login (search engines, hotlinks, scraped `/media/` trees; persona artwork may additionally be copyrighted material). Each file is now served only through an authenticated endpoint - `GET /api/drill-instructor/persona/<id>/picture/` (any logged-in user) and `GET /api/user/<id>/picture/` (the owner or a co-participant; `/api/user/me/picture/` works too): Django checks the JWT and hands delivery to nginx via `X-Accel-Redirect` from a non-public `internal` location (`/protected-media/`). The whole `/media/` tree now answers 404 from the outside. Responses carry `X-Robots-Tag: noindex, nofollow` and `Cache-Control: private, no-cache` (the URLs are stable per user/persona, so browsers revalidate via ETag and see an uploaded replacement immediately, while shared caches never store the bytes). The API payloads (user, persona, drill-message, leaderboard stats) expose only these endpoint URLs (uploads moved to write-only `profile_picture_upload` fields), and the frontend renders the images from object URLs fetched with the JWT (`blob:` added to the CSP `img-src`). Browser push icons intentionally fall back to the built-in artwork for pictured personas - notification icons are fetched by the browser without credentials.

- **Remaining Dependabot highs eliminated via `overrides`** — `underscore ^1.13.8` (jsonpath/bfj chain, semver-safe), `serialize-javascript ^7.0.7` (forces both the terser-webpack-plugin and the abandoned workbox `rollup-plugin-terser` copies past the patch), and `@svgr/webpack ^6.5.1` (drags svgo 1.3.2 → 2.8.3+ and nth-check 1.0.2 → 2.1.1; safe here because the project never imports SVGs as React components, so the loader code path never executes). Production build verified with all overrides. What stays open is not upgradable or not applicable: `postcss@7` via `resolve-url-loader` (API-incompatible with postcss 8; runs only on our own checked-in CSS at build time), the `webpack-dev-server`/`sockjs`/`uuid`/`@tootallnate/once` dev chain (`npm start` only, never in the shipped bundle, no v4 backports exist), and the react-router RSC advisory (no SSR/RSC in this SPA). The structural cure for this whole alert class remains the react-scripts → Vite migration.
- **CodeQL code-scanning findings (9)** — (1) tainted-format-string in the competition page's error `console.log` (URL param was concatenated into the format position; now passed as a separate argument); (2) eight `py/stack-trace-exposure` spots where raw exception text went into HTTP responses - the celery task admin views, the Garmin link/sync views (upstream errors can echo account details), and the push test-ping endpoint, which now returns status-mapped hints + exception type instead of provider error bodies. All affected views log the full exception server-side.
- **npm dependency audit (107 Dependabot alerts)** — `react-router-dom` bumped `^7.5.1 → ^7.18.2` (clears all 15 react-router advisories incl. open redirects and the vendored `turbo-stream` RCE) and `lodash` `^4.17.21 → ^4.18.1` (template code-injection + prototype pollution) - both shipped in the browser bundle; a semver-safe `npm audit fix` pass on top cleared every **critical** alert (form-data, shell-quote, websocket-driver) and most highs. What remains is build-time-only (react-scripts/webpack chain - svgo, postcss, nth-check, workbox, …) which never ships to users' browsers, plus one react-router RSC-mode CSRF advisory (GHSA-qwww-vcr4-c8h2) that only affects framework-mode server actions - this app is a client-side SPA without SSR/RSC, so the vulnerable code path does not exist. A full structural fix means migrating off `react-scripts` (e.g. Vite) - tracked separately.
- **Arbitrary points minting closed** — `POST /api/point/` was a full `ModelViewSet` whose permission class lets any authenticated user through while `create()` never runs object-level checks, so anyone could forge `points_raw`/`points_capped` for any goal and any (even someone else's) workout. The endpoint is now read-only; points are computed exclusively by the scorer.
- **Stats cache no longer bypasses authorization** — `CompetitionStatsQueryView` is wrapped in `cache_page(30)`, and the competition-membership check only ran inside the view body, so on a cache hit any authenticated user could read the stats of a competition they don't participate in. The check now lives in `has_permission`, which DRF runs before the cache lookup.
- **Cross-account workout takeover via Strava sync closed** — `sync_strava` updated any existing workout matching a `strava_id` (unique across the whole table) and reassigned it to the syncing user. It now only touches workouts the syncing user actually owns.
- **Strava refresh tokens encrypted at rest** — they were stored plaintext while Garmin tokens were already Fernet-encrypted. Both now go through the shared `custom_user/token_crypto.py` (key from `GARMIN_TOKEN_KEY` or `SECRET_KEY`); existing plaintext rows keep working and are re-saved encrypted on their first successful use. Migration `custom_user/0006` widens the column for the ciphertext.
- **Container hardening** — gunicorn, celery worker/beat and Flower now run as an unprivileged `app` user and Redis as the `redis` user (previously everything ran as root); the container drops all capabilities and adds back only what it needs (`NET_BIND_SERVICE`, `SETUID`/`SETGID`, `CHOWN`, `DAC_OVERRIDE`) plus `no-new-privileges`. Gunicorn binds loopback (nginx proxies internally) and is no longer published to the host; the unauthenticated supervisord web UI binds loopback inside the container and its host port mapping is removed (use `docker compose exec workoutchallenge supervisorctl -c /etc/supervisord.conf status`); Redis binds localhost only.
- **Flower requires basic auth** — the task-monitoring UI exposed task payloads and controls without any login. It now defaults to `admin` / your `SECRET_KEY` (override with `FLOWER_USER` / `FLOWER_PASSWORD`).
- **`SECRET_KEY` required, `DEBUG` off by default** — docker-compose refused neither the publicly-known dev key nor `DEBUG=true` before; both are now hard/opt-in like `POSTGRES_PASSWORD`.
- **Stricter Content-Security-Policy** — `script-src` no longer allows `'unsafe-inline'`: the frontend builds with `INLINE_RUNTIME_CHUNK=false` and the pre-paint theme bootstrap moved to the external `/theme-init.js`. Also: `server_tokens off`, and the `/api/` error log dropped from `debug` (it recorded join-token URLs) to `warn`.
- **JWTs no longer written to the browser console** — three auth-flow log lines printed the full access token, which Sentry breadcrumbs would have shipped off-site on any error.
- **Authenticated API cache purged on logout** — the service worker keeps `/api/*` responses as an offline fallback; they are now deleted on logout so a shared device can't read the previous user's data.
- **GitHub Actions pinned to commit SHAs** — all workflow actions (checkout, docker setup-qemu/buildx/login/build-push, github-tag-action) were mutable tags that a supply-chain repoint could use to exfiltrate DockerHub credentials or push to the repo; they are now SHA-pinned, `actions/checkout` upgraded v2/v3 → v4, and every job declares a minimal `permissions:` block.
- **Smaller fixes** — user-controlled path segments are URL-encoded in the join/Strava-link API calls, all `target="_blank"` links carry `rel="noopener noreferrer"`, password-reset lookup is case-insensitive (mixed-case registrations previously never got the email), Strava API calls have hard timeouts, sync logs no longer print user email addresses, and the dev DB-clean script no longer deletes files inside the machine's installed Django packages.

### Security (audit, 2026-07-31)
- **CRITICAL**: `my_competitions`/`my_teams` made read-only in `CustomUserSerializer` - closed a mass-assignment hole that let any user join any competition/team via `PATCH /api/user/me/`, bypassing join codes.
- **CRITICAL**: password changes via `PATCH /api/user/me/` now hash via `set_password()` - the default DRF `update()` had stored plaintext passwords.
- **HIGH**: persona IDOR closed - custom personas can only be edited/deleted by their creator or staff (was: any user, enabling cross-competition prompt injection).
- **HIGH**: other users' `garmin_email`, goals, scaling factors, competition/team rosters and settings no longer exposed to co-participants (`PRIVATE_FIELDS` omit list).
- **HIGH**: Strava linking now uses a signed, 10-minute OAuth `state` token (`/api/strava/state/`) binding the flow to the initiating session (login-CSRF protection).
- **MEDIUM**: DRF throttling enabled - baseline anon/user buckets plus strict `auth` (30/h) on token obtain/refresh + password reset and `join` (60/h) on competition joins.
- **MEDIUM**: registration throttle now keys on the LAST `X-Forwarded-For` entry (first entries are spoofable).
- **MEDIUM**: competition join codes use `secrets` (CSPRNG) instead of `random`.
- **MEDIUM**: password reset now blacklists outstanding refresh tokens, sends mail asynchronously (kills the SMTP timing oracle), returns a uniform error, and validates password strength (as do registration and password changes).
- **LOW**: `organizer_assigns_teams` enforced in join/create team views; email changes reset `is_verified`; `JoinTeamView` rejects non-numeric ids; public usernames no longer derived from the email local-part; nginx security headers fixed for `/media/` + `/apistatic/` (inheritance no longer broken by `add_header`).
- `requirements.txt` malformed `py-vapid…Pillow` line fixed.

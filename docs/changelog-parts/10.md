- **Open Wearables bundled into the main `docker-compose.yml` (opt-in `health` profile)** — no second stack to deploy: `docker compose --profile health up -d` builds and runs the whole Open Wearables instance (API + worker + beat + own Postgres + own Redis, image built from the pinned upstream commit `27ccd87`, since no official image is published). `HEALTH_BASE_URL` defaults to the internal `http://openwearables:8000`; the connector authenticates with the seeded OW admin developer (defaults `admin@example.com` / your `SECRET_KEY`, overridable via `OW_ADMIN_*` / `HEALTH_DEVELOPER_*` / Site Settings), so **no API-key minting step is needed at all**. A new `HEALTH_PUBLIC_URL` (Site Settings too) separates the phone-facing address shown in connection codes from the server-internal one. The API publishes on `127.0.0.1:8001` by default (`OW_BIND`/`OW_PORT` knobs) for reverse-proxy fronting.
- **Apple Health / Google Health Connect import via Open Wearables (new connector, Strava fully optional)** — a third activity source that reaches the two on-device health stores no cloud API exists for. The server polls a self-hosted [Open Wearables](https://github.com/the-momentum/open-wearables) instance (MIT, deploys beside this stack) whose phone app pushes Apple HealthKit / Health Connect workouts up from the device. Connector follows the established Strava/Garmin shape: instance URL + developer login in Site Settings/env (DB-over-env, password write-only + masked; a developer JWT works on every OW endpoint, so one credential pair covers polling and onboarding - login is cached and retried on 401); linking creates the OW user once (UUID stored on the user; an existing OW account with the same email is adopted on 409) and returns a single-use invitation code the athlete enters in the health app; hourly Celery beat poll (minute 34, 10 min before Strava) with 55-min per-user throttle plus a manual re-sync button on Home; dedup by the OW workout UUID (`Workout.health_id`) plus the cross-provider duplicate guard; ~80 HealthKit/Health Connect type names mapped (camelCase and UPPER_SNAKE normalized, unknown types fall back to `Workout`); intensity estimated from avg HR / kcal like Garmin. The one-source-per-user selector now handles three providers (first linked wins, explicit choice in Settings, Strava stays the legacy fallback), the settings UI offers the Health section only when the server has the connector configured (new `health_configured` flag on the user payload, one query per request), and unlinking clears a stale source selection. 17 new tests cover mapping, source resolution, sync dedup and the link/unlink/sync views.
- **Strava subscription note in the personal settings** — under the Strava link button: since Strava's June 2026 developer-program change, an active paid Strava subscription can be required for an athlete to connect third-party apps (API Policy §3.3, Standard Tier), so a failed linking attempt on Strava's side most likely means the athlete's own subscription is missing - not an app problem.
- **"Respond" button on the Coach page** — the On-duty hero's speech bubble now offers a respond link that jumps straight into the matching thread: it deep-links to `/competition/<id>?reply=<messageId>`, where Coach's Corner scrolls into view and that thread opens expanded, ready for a reply.
- **"What's new" release popup** — after every release, each user gets one popup with the changelog and a reload button. The CI-built image now carries the git tag as `APP_VERSION` (build-arg wired through `prod-deploy.yml` → Dockerfile; "dev" disables the popup for local builds) plus a copy of `CHANGELOG.md`. A new public endpoint `GET /api/version/` returns the version and the newest changelog section parsed for small screens (`workout_challenge/release_notes.py`: first `## [...]` section - `[Unreleased]` shows as "Latest changes" until version headings are adopted, markdown markers stripped, 4 sections / 12 items / 240 chars per item caps, mtime-cached). The frontend polls it on start and every 15 min (catches tabs left open across a deploy) and compares it to a `localStorage` seen-marker: first visit only records the version (no bombardment), every later release shows the popup exactly once - dismissed via "Later", the X, the backdrop, or the "Reload" button, which also guarantees the device runs the fresh build.
- **Coach threads: participants can talk back to the Drill Instructor** — every coach message in the competition's Coach's Corner is now a conversation. Any participant (owner included) can post a reply under it (new `POST /api/drill-instructor/message/<id>/reply/`, participant-only, 500 chars max, 10 replies/hour/user as an LLM-cost cap), and the coach answers each reply in its persona's voice a few seconds later (new `post_reply_reaction` Celery task with a `build_reply_prompt` that sees the original message plus the thread so far; static fallback on LLM outage). Replies and reactions are one-level threads on `DrillInstructorMessage` (new `parent` self-FK + `user` FK + `reply`/`reaction` kinds, migration `drill_instructor/0011`); the feed endpoint lists thread roots with replies nested oldest-first. The UI expands inline under each message: participant bubbles with profile picture + first name, coach bubbles with the persona's avatar/accent, and a compact reply box ("Reply to <persona>…", Enter to send) that appears only while the coach is on duty - benched coaches keep their threads readable. The replier gets a push ping with the coach's reaction when the competition's push toggle is on (to them only, not the whole group), and the persona's recent-message memory excludes participant replies so it stays in its own voice.
- **One activity source per user (no more doubled workouts)** — the same physical activity usually exists in both ecosystems (recorded on a Garmin watch, auto-synced to Strava), and until now a user with both providers linked got every workout twice: each sync only de-duplicated by its *own* provider id. Every user now resolves to exactly one import source (new `CustomUser.activity_source`, migration `custom_user/0007`): with only one provider linked it is that provider; with both linked it is an explicit choice shown as an **"Activity import source" selector** in the personal settings (falls back to Strava for legacy rows). The first linked provider becomes the source automatically, and the initial ~6-week import at link time only runs when the newly linked provider is the active source - otherwise the link response says so. The beat tasks, the per-user sync tasks and the manual re-sync buttons all refuse to run for the non-selected source (with a 400 pointing at the settings), and the dashboard hides the inactive source's re-sync button. As a second layer of defence, both syncs now skip creating a workout when the same user already has one with matching start time (±10 min) and duration (±5 min) from the other provider or a manual entry - so switching the source or re-linking never doubles history either (the Strava skip happens before the details request, saving API quota). The profile's "Update" button no longer sends the source field, so it can't revert a selector change with a stale snapshot.
- **Drill Instructor remembers its past two messages** — workout comments, quiet-day nudges and random pep talks are now generated with the persona's two most recent messages (per competition, newest first; test previews and failed generations excluded) as prompt context. The coach can refer back for continuity (callbacks, running jokes, "as I said this morning…") and - just as importantly - knows what NOT to repeat, which makes it feel noticeably more natural. Bodies are clamped to 220 chars each so history can't blow up the prompt, and the user-prompt clamp was raised accordingly.

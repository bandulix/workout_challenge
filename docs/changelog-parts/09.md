- **Home welcome block is compact now** — smaller profile picture with the name beside it and smaller type, matching the lean competition header style.
- **Competition header: title gets its own row** — the name was truncated between the workout count and the action buttons in smartphone view; it now spans the full width with counts + icon actions on a second row.
- **Refresh Competition button removed** — the page refreshes itself: when the Drill Instructor posts a new comment (fired right after a workout is logged and scored), feed/stats/competition refetch automatically (60s poll, cache shared with the Coach's Corner). The existing 90s polling stays as fallback for competitions without a coach.
- **Home screen reordered** — the 30 Day Activity block (with personal goals and streak) now sits directly under the welcome block, above My Workouts; the workout list shows only the 5 most recent trainings, explicitly sorted newest-first (header notes "latest 5").
- **Strava & Garmin now sync every hour** — the beat schedule was once per day (04:44 / 04:54) and both sync tasks additionally skipped any user synced within the last 6 hours, so a workout could take over a day to show up. The `strava_sync` / `garmin_sync` PeriodicTasks now run hourly (:44 / :54, kept 10 minutes apart so they never compete for the worker) and the per-user throttle is lowered to 55 minutes, so activities land in the app at most ~1 hour after recording. Strava API usage stays far below the rate limits (one list request per user per run; detail requests only for new activities).
- **Login now lasts a month of inactivity** — the JWT refresh token lifetime was raised from 5 to 31 days (`JWT_REFRESH_DAYS` env var). With token rotation the validity re-extends on every app use, so active users never see the login screen again; a login is only required after ~1 month without opening the app. Existing sessions pick up the new lifetime automatically at their next refresh.
- **Drill Instructor personas are admin-managed now** — previously any authenticated user could create personas and edit their own, which meant a regular user could rewrite the system prompt of a persona on duty in someone else's competition (prompt-injection-as-a-service). Persona create/update/delete is now staff-only end to end: the API returns 403 for non-staff writes, and the Coach page only shows the "Manage" button (and its persona editor) to admins. The library stays readable for everyone, so challenge owners can still pick any persona for their competition. The persona's "Voice & style briefing" (the system prompt) is also admin-only now - it is neither serialized for regular users nor rendered in the Coach page's persona detail dialog.
- **Coach page reworked** — the "Coach wire" message list is gone (the hero's speech bubble still shows the latest coach message). In its place, a "My challenges" block sits directly under the "On duty" hero: every challenge with its date range and a Running/Upcoming/Finished chip, one tap straight into the competition page. The page is now a single column (hero → My challenges → push opt-in → the roaster).

### Removed
- **Django admin link in Admin Settings** — it pointed at `/admin/...`, which the container nginx deliberately does not expose (only `/api/` is proxied; everything else serves the SPA), so the link always landed on a broken page. Site settings are managed in the app's Admin Settings UI.
- **Postgres host port mapping** — the `database` service no longer publishes `5432` to the host; it was optional and only used for host-side `psql`. The `POSTGRES_BIND` / `POSTGRES_HOST_PORT` env vars are gone with it. If a running deployment previously relied on the mapping, connect via `docker compose exec database psql -U postgres workoutchallenge` instead (and delete the two vars from your `.env` if you added them).

### Added
- **Releases now ship the APK automatically** — a new `apk` job in `prod-deploy.yml` builds a generic Android APK on every release (Node 20 + JDK 21 + Android SDK 36, version-stamped from the tag and commit count) and attaches it plus `apk-version.json` to the GitHub Release. `scripts/update_apk_from_release.sh` fetches it onto a deployment (optionally from cron, optionally for a specific tag), so the app and the in-app update banner always match the deployed version - the "whatever we deploy, the APK follows" guarantee.
- **Native coach pings in the Android app** — Web Push (VAPID) does not work inside an Android WebView, so the app now raises real Android notifications itself: it polls the coach feed while logged in and notifies on new coach-authored messages (workout comments, random group pushes, quiet-day nudges, and the coach's reactions to your replies - thread nesting included). Baseline on first run (no history spam), permission asked once (Android 13+), silent when logged out or denied - no Firebase, no server changes (`@capacitor/local-notifications` + `utils/nativeCoachPings.js`).
- **Activity-source switching works in the Android app too** — the Settings selector (Strava / Garmin / Google Health Connect) now drives the phone-side sync as well: switching to Health starts the native background sync, switching away pauses it (new `stopSync` bridge method + `nativeHealthSetSource`), so the phone never burns battery pushing workouts the server would skip anyway. Switches made on *other* devices reconcile on the next app start (bottomNav watches `activity_source_effective`).
- **In-app update check for the sideloaded APK** — `build_apk.sh` stamps every build with `versionName` (git tag) and a monotonic `versionCode` (commit count) and publishes `apk-version.json` next to the APK on the stack. The app compares its own build (`@capacitor/app` `getInfo`) against it and shows a dismissible "App update available" banner on the dashboard that links the download; Android installs it over the top (same signing key = update, all data kept). Dismissal is remembered per versionCode, so it re-appears only for the next newer build.
- **Native Android app (sideload APK) with built-in Health Connect sync** — the PWA now also ships as a Capacitor Android app (`src-frontend/android/`) with the Open Wearables Android SDK bridged into the web app via a custom Kotlin plugin (`OWHealthPlugin`: configure/sign-in/permissions/background-sync/status/sign-out, pinned to SDK `v0.9.0` via JitPack). Inside the app, *Settings → Apple / Google Health* turns into a one-tap flow: the app redeems the connection code itself against OW's public endpoint, shows the Health Connect permission dialog and starts the WorkManager background sync - no second app, no code typing (`utils/nativeHealth.js`, gated behind `Capacitor.isNativePlatform()`; browsers keep the manual code flow). Release builds sign from `~/.gradle/workout-signing.properties` (outside the repo, debug-key fallback) so a Play Store AAB stays possible later.

### Fixed
- **Coach sometimes posted the same message twice** — the workout-comment task had no idempotency guard, so any double enqueue (double submit, a sync re-import edge case, broker redelivery) produced two identical coach messages. Now DB-enforced: a conditional unique constraint (`config` × `workout` for activity comments) plus a pre-check and silent `IntegrityError` skip on losing the race - one comment per competition per workout, guaranteed at the database level. The two daily sweeps (random group pushes, quiet-day nudges) additionally got the overlap guard so a slow LLM run can't collide with its own next beat tick, and the shared `is_task_already_executing` helper no longer crashes when no worker answers (tests, broker still starting).
- **Settings modal crashed after linking a provider** — the `*_last_synced_at_fmt` values produced by the usersSlice transform are *objects* (`{epoch, date_readable, time_24h, …}`), but the Health and Garmin sections rendered them directly as React children, so the modal died with React error #31 ("Objects are not valid as a React child") as soon as a linked provider had a sync timestamp - e.g. right after a successful "Connect Health App" click. Both sections now render the object's `date_readable`/`time_24h` properties (the Garmin one was a latent pre-existing crash for synced Garmin users). Verified headlessly (Playwright): section renders, invitation code shows, zero page errors.
- **Competition page scrolled sideways on smartphones** — coach messages and thread replies (LLM pep talks with hashtag chains, pasted URLs) contained long unbreakable strings that couldn't wrap, so the thread column pushed past the viewport and the whole page could be scrolled left/right a bit. All coach/reply bodies now wrap with `break-words` (competition Coach's Corner, thread replies, and the Coach page hero bubble for the same content class).
- **First name crushed in the Home welcome block on smartphones** — the one-row header squeezed the name between the fixed 64px avatar and the always-visible workout counter (~10 characters survived on a 360px screen). The header can now wrap onto a second row on narrow widths (the counter drops below, right-aligned), so the name gets the full row first; on wider screens nothing changes.
- **Login (and every user query) 500s after pulling a newer image** — the migration modules for `competition` / `custom_user` / `workouts` lived at `src-backend/data/db_migrations/`, i.e. *inside* the `django_data` runtime volume. A named Docker volume is seeded from the image only on first creation and shadows that path forever after, so `manage.py migrate` at container start could only ever see the migrations of the *first* image ever deployed - never the ones baked into an update. Code from a newer image then queried columns the schema never got (e.g. `custom_user.activity_source` from migration `0007`), and Postgres answered `ProgrammingError` → HTTP 500 on `/api/token/` and every authenticated request. The migration modules moved to `src-backend/db_migrations/`, outside the volume (`MIGRATION_MODULES`, `manage.py`, `.gitignore`, `.dockerignore`, Dockerfile comment, dev-clean script updated). **Upgrade note:** existing deployments keep working - the DB records applied migrations by app+name, not by module path, so the next container start simply applies the migrations it had been denied (no manual volume surgery needed). The stale `data/db_migrations/` copy inside old volumes is dead weight and can be ignored.
- **White screen of death from new Strava sport types** — Strava added Basketball, Cricket, Dance, Padel, Physical Therapy and Volleyball as sport types (API changelog 2026-04-30), and the Strava sync stored `sport_type` verbatim (`choices` on the model are not DB-enforced). Six label lookups in the dashboards (`workoutTypes[sport_type].label_short` on the Home and competition pages, incl. other participants' feed entries) then threw a `TypeError`, and with no error boundary the whole React tree unmounted: users whose recent workouts used one of the new sports saw the app fail to start intermittently (only while such a workout was in the latest-5/top-4 windows) and couldn't reach the settings. Three layers of defence: (1) all label lookups now go through `sportLabelShort()`, which falls back to the raw type name instead of throwing; (2) the Strava sync maps unknown sport types to `Workout` before they reach the database; (3) a top-level error boundary now catches any render error and shows a recovery screen with a **reload button** instead of a dead white page.
- **Tapping "Settings" silently did nothing when the profile wasn't loaded** — the Me sheet only rendered the settings modal when the `user` query had data, so on a slow or failed `GET /api/user/me/` the sheet closed and no modal appeared. The tap now always opens the modal, showing a spinner while loading or an error with a retry button.
